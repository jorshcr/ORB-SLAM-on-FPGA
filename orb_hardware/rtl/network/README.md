# ORB UDP prototype

The separate `orb_udp_board_top` target connects the current three-level ORB
system to a hardware IPv4/UDP/ARP stack and 100 Mb/s RMII MAC. The existing
`orb_board_top` and its build are unchanged. This new board top is a snapshot
of the existing camera/scaler wiring; keep shared wiring in sync when changing
the original board top.

Dependencies are vendored under `third_party/verilog-ethernet`, pinned to
`sifferman/alexforencich_ethernet` commit
`55b75042b0fdfeaca870b253f93d1dcfd9173b24`, the RMII/Nexys A7 contribution in
[upstream PR 267](https://github.com/alexforencich/verilog-ethernet/pull/267).
This is a contributed implementation, not an upstream release. MIT licenses
are retained; `manifest.json` records original file hashes. `orb_udp_stack.v`
adapts the example core, preserving its license.

## Data path

Descriptor FIFO → packetizer → UDP/IP/ARP → Ethernet framing → asynchronous
MAC FIFOs → RMII PHY. Logic runs at 100 MHz; RMII uses an FPGA-generated 50 MHz
clock generated by an MMCM. The PHY reference leads the MAC clock by 1 ns;
RX setup explicitly selects the following MAC cycle, with default hold timing
retained. TX pins are retimed on the falling edge. PHY/capture reset is held for
approximately 42 ms while reference clocks run. RMII timing constraints retain
the forwarded-clock relationship and assume +/-1 ns PCB skew.

Each FIFO record is latched before transmission; valid/ready backpressure
propagates to the descriptor FIFO. The angle stays in the same record. The
camera itself cannot pause during an admitted frame, so existing ORB overflow
and drop flags remain relevant.

## PC connection

Defaults: FPGA `192.168.1.128`, PC `192.168.1.100`, subnet `/24`, UDP port `5000`,
locally administered MAC `02:00:00:00:00:01`. Configure the PC's Ethernet adapter
on that subnet, allow inbound UDP 5000, and connect a cable. These are parameters,
not DHCP settings. The stack answers ARP and resolves the PC MAC address.

Run `python orb_hardware/scripts/receive_udp.py`; it prints JSON lines. It checks
packet lengths, descriptor indices, duplicates, and completeness at each end
marker. Out-of-order delivery after a marker can make that immediate check
incomplete. UDP has no retransmission or acknowledgment in this version.

The MAC is fixed at 100 Mb/s; the PHY uses its board straps/autonegotiation.
Use a 100 Mb/s full-duplex link. MDIO management, speed detection, capture
commands and delivery acknowledgments are not implemented. Inbound UDP is
drained; ARP is handled by the stack. The existing frame controller automatically
captures subsequent frames; it does not wait for a PC acknowledgment.

## Payload (network byte order)

| Bytes | Field |
|---|---|
| 0–3 | ASCII `ORB1` |
| 4 | Type: 0 descriptor, 1 frame end |
| 5 | Sticky error flags |
| 6–7 | Record count: 1 descriptor, 0 frame end |
| 8–11 | Transport frame number |
| 12–15 | Descriptor index; frame end carries total descriptor count |
| 16–51 | Descriptor only: `{5'b0, octave[1:0], pos[18:0], angle[5:0], descriptor[255:0]}` |

`pos={x[9:0],y[8:0]}`. The first frame/index are zero. Frame numbering is added
at transport completion boundaries, not propagated through pixel processing.
This relies on the current capture/drain controller and ordered descriptor FIFO.
One record per packet simplifies the initial implementation; batching is future work.

Flags bits 0–4: camera overflow, keypoint FIFO overflow, BRIEF drop,
network error (ARP failure/TX underflow/RX FIFO overflow), frame-marker overflow.
They remain asserted until reset where their producers are sticky. A bounded
one-marker queue preserves a completion while a packet is stalled. If another
frame completes before space is available, marker overflow is reported; the
receiver must discard incomplete frames. No claim of lossless operation during
link outages is made. Frame-end means processing drained into transport, not
that the PC received it. Empty frames still send an end marker.

## Validation/build

`python orb_hardware/scripts/udp_check.py` compiles the dependencies, elaborates
the whole board, and tests packet formatting, metadata, backpressure, ordering,
sticky completion and empty frames. This is not a PHY/link hardware test.

`vivado -mode batch -source orb_hardware/scripts/check_udp_board.tcl`
synthesizes the new target. Add final arguments `-tclargs --route` for full
implementation. It applies vendor CDC constraints after synthesis. Existing
ORB timing snapshots do not apply to this larger target. Do not claim board
timing closure until its routed reports pass, including RMII I/O and CDC review.

The local `orb_rmii_cdc.tcl` extends the upstream MAC status-synchronizer filter
to include `eth_mac_rmii_fifo`; upstream's filter does not recognize that name.
The three-level 2/2/1 BRIEF configuration has routed timing results documented
under docs/synthesis. The current BRIEF pattern uses OpenCV's bit_pattern_31_
and nearest-pixel coordinate rounding. Earlier dataset comparison results used
the previous custom pattern. No hardware has been programmed or Ethernet link tested.
