# ORB synthesis and timing snapshot - 2026-11-24

Synthesis, placement, and routing completed. The design fits the target FPGA, but **timing does not close at 100 MHz**. This snapshot records the current implementation without timing-driven RTL changes.

## Configuration

- Vivado 2024.1, build 5076996; `xc7a100tcsg324-1` (Nexys A7-100T).
- Top: `orb_pyramid_level`, 640x480, three BRIEF engines, keypoint FIFO depth 512.
- Out-of-context synthesis, optimization, placement, routing.
- Clock period: 10.000 ns; input/output delays: max 2.000 ns, min 0.000 ns.
- The existing script applies timing constraints after synthesis, before implementation. Synthesis itself is not clock-constrained.
- Branch: `orb-slam-rebuild`; base HEAD: `038fc9968ae7fffb4f1a342d6a6fd4f13c87244a`.
- Includes uncommitted working-tree changes. Commit this snapshot with the corresponding RTL; the base HEAD alone does not reproduce it.
- Original run: `orb_test_output/orb_20261124_014216`.

Includes the internal 7x7 input window, FAST/NMS, Gaussian, blurred-column storage, orientation with sine/cosine lookup, keypoint FIFO, priority arbiter, column alignment, and three BRIEF engines. BRIEF uses 6-bit pixels, a custom 256-pair pattern, and runtime coordinate rotation. Intermediate diagnostic ports are now internal; external outputs are descriptor-valid/data, position, score, and loss flags.

Output collection/backpressure, explicit frame handling, multiscale pyramid generation, and host integration remain outside this implementation.

Critical setup path: `g_brief[2].brief/pair_index_reg[3]/C` to `g_brief[2].brief/y_rotated_reg[1][1]_rep__6/D`.

- Stage: pair-pattern selection through coordinate rotation.
- Data-path delay: 10.702 ns; logic 3.909 ns, routing 6.793 ns.
- 12 logic levels. Separating lookup from rotation is a candidate for the next timing experiment; it was not implemented in this snapshot.

Worst hold path: `in_x[5]` to `pixel_window/lines_reg_0/ADDRBWRADDR[10]`.

All 39,525 routable nets are fully routed, with zero routing errors. Vivado reports no unconstrained internal endpoints or missing input/output delays. However, `HD.CLK_SRC` and boundary `HD.PARTPIN_LOCS` are unset, so clock skew/insertion and boundary timing are not fully modeled. This is an out-of-context baseline, not board-level timing sign-off. Hold violations must not be treated as resolved.

## Validation

`python -B orb_hardware/scripts/fast_check.py --quick` passed after the port cleanup: 502 line-window checks and six frame runs across 64x48 noise, 100x50 noise, and a 160x120 scene, with and without valid gaps. The testbench checks FAST reference results, orientation, FIFO ordering, BRIEF priority, descriptor values, metadata, and completion timing. Diagnostic signals are observed hierarchically.
