# One TUM frame through camera, ORB and Ethernet — 2026-11-25

Run `python -B orb_hardware/scripts/frame_udp_check.py` with Vivado 2024.1.
Input: previously downloaded TUM Freiburg1 desk image, converted to 640x480
grayscale and sent in OV7670-style UYVY byte order. Three ORB levels use
2/2/1 BRIEF engines. The test instantiates the current complete UDP board top,
including MMCM, camera clock crossing, scalers, frame controller, descriptor
FIFO, packetizer, UDP/IP stack, MAC and RMII output.

The PHY startup delay is shortened in simulation. Destination IP is broadcast
to avoid requiring an ARP responder. No RX PHY/ARP peer or physical link is
simulated. Input PCLK is 25 MHz. This is a digital RTL integration test, not
post-route timing simulation or independent software descriptor verification.

Results:

- All 307,200 pixels captured.
- 1,124 descriptors: octave 0 = 521, octave 1 = 373, octave 2 = 230.
- 1,125 transmitted Ethernet frames: 1,124 descriptors and one frame-end marker.
- Every accepted descriptor, coordinate, angle, octave, index and error flags
  matched the packetizer output exactly.
- RMII dibits decoded to the same ordered UDP payloads without missing packets.
- Every Ethernet preamble/FCS and IPv4 header checksum passed.
- Frame-end count matched the accepted descriptors; capture/drain completed.
- BRIEF-drop flags were set on all three octaves, indicating dense bursts
  exceeded engine availability. This pass does not claim all keypoints received
  descriptors. Camera/keypoint FIFO overflow, network and marker errors were absent.

Artifacts: `orb_test_output/frame_udp_2026-11-25/`: summary.json, descriptors.txt,
udp_payloads.hex, ethernet_frames.hex and simulation/compiler logs.
